# 灵稿 AI

灵稿 AI 是一款内容创作桌面应用，支持选题、多平台文案与配图创作。

## 开发

需要 Node.js 20.19 或更新版本，以及 npm。

```bash
npm install
npm run dev
```

- `npm run typecheck`：检查主进程、预加载脚本和界面的 TypeScript 类型。
- `npm run build`：类型检查并构建到 `out/`。
- `npm test`：运行本地草稿与生成流程的针对性测试。
- `npm start`：预览已构建的应用。

`src/main` 管理应用窗口，`src/preload` 是安全通信边界，`src/renderer` 存放 React 界面。后续开发请遵循 [AGENTS.md](./AGENTS.md)。

## 设置

在桌面应用的「设置」中选择本地草稿目录并保存；草稿目录没有默认值。API 地址和模型名称可在设置中覆盖本机默认配置。手动输入的密钥由 Electron 使用系统安全存储加密；如果系统安全存储不可用，密钥不会保存。密钥不会回显，可替换或清除。旧版页面存储中的 API 地址和模型名称会在同一运行环境打开设置时迁移；开发环境与打包环境的页面存储彼此独立。

本机默认模型配置从项目根目录的 `.env` 读取，支持 `REVIEW_MODEL_BASE_URL`、`REVIEW_MODEL_NAME`、`REVIEW_MODEL_API_KEY` 和 `REVIEW_IMAGE_MODEL`。该文件被 Git 忽略，其中的默认密钥以明文存储，请勿提交或分享；应用设置中手动保存的密钥使用系统加密。设置中清除密钥也会禁用默认密钥，重新输入密钥可启用。模型使用兼容 OpenAI Chat Completions 的接口，具体兼容性取决于服务商。

「平台生成规则」可分别设置小红书、公众号和抖音图文的写作要求，并可逐项恢复默认；留空时使用默认规则。文章按各自平台的标题规则和正文规则直接生成。联网资料作为参考。规则保存在本机设置中，也会包含在加密工作空间备份里。

## 选题

通过侧边栏「选题」输入内容方向，通过滑动条选择生成 1–20 条候选（默认 5 条），默认通过当前模型服务的联网搜索检索公开资料。页面展示检索来源、读取状态及生成进度；联网失败时可重试或跳过联网。提交后立即在「选题记录」显示排队或生成进度，最多同时执行 3 个选题任务；成功后可查看选题，失败或中断后可手动重试。选题记录和创作任务保存在当前工作空间，并随工作空间备份；生成期间可以切换页面。可选择一个选题编辑创作信息，也可勾选多个选题批量创作，逐篇查看成功或失败结果。应用关闭后未完成的选题及批量创作任务会标记为中断，不会自动重新运行。推荐平台仅供参考；选题来源与生成内容均需人工核查。

## 内容工作区

草稿保存在选择的目录下，按 `主题/平台/发布文案.md` 组织。选择主题和平台后可编辑、预览和保存；点击文章会先保存当前及目标文章的未保存修改，再重新读取目标文章。保存或读取失败时保留未保存内容；检测到外部修改时，请先复制自己的修改再处理冲突。每个平台可生成优化候选，核查后决定是否应用，应用后仍需保存。新建内容会按平台调用模型，成功的文案分别保存；同名主题不会覆盖。文案生成默认检索公开资料，检索失败时可选择跳过；检索结果和文案仍需人工核实。文章正文以 Markdown 直接编辑并保存。


## 封面和配图

在设置的「图片生成服务」中配置图片模型名称（可使用本机 `.env` 中的默认模型），可选择复用文案模型的服务地址与密钥，或单独配置兼容 OpenAI 图片生成接口的服务。进入草稿并选择平台，在保存文案后点击「生成配图」；每次生成一张封面，并根据文章内容策划 4–6 张正文配图。新建文章时可勾选生成配图（默认不勾选），再选择清新扁平、手绘插画、水彩或极简信息图风格；文案成功保存后会为成功的平台分别生成配图。空白文章需先填写并保存文案，再生成配图。文章详情中点击“生成配图”会先展示风格示意供选择；风格保存在工作空间中。配图策划使用已配置的文案模型，图片接口按张调用。

图片保存到对应的 `主题/平台/图片/`，文件名按序编号，已存在的图片不会覆盖。生成后可在应用中预览；部分失败时成功图片会保留。生成图片需要逐张检查文字、事实、隐私与画面，图片结果不代表已核验。接口支持 base64 图片数据和可公开访问的 HTTPS 图片地址；不跟随图片地址的重定向。

## 代码结构

- `src/main/ipc`：接收并校验来自渲染进程的请求，转发给业务能力。
- `src/main/features`：按草稿、内容生成、资料检索、图片和设置组织业务逻辑与本地存储。
- `src/main/infrastructure`：模型服务及通用网络安全能力；`composition.ts` 负责连接业务与运行时依赖。
- `src/preload` 和 `src/shared`：定义并暴露类型明确的跨进程接口。
- `src/renderer/src/features`：按页面功能组织界面组件；`App.tsx` 管理工作区级状态。

应用服务通过注入的能力进行测试，避免测试时依赖真实模型或网络。草稿和设置仍使用原有本地格式。

## 工作空间与备份

在「设置」的「工作空间管理」中新建或打开工作空间；原有草稿目录也可以直接打开。左侧目录用于分类，不移动原始草稿文件；删除目录会将其中的文章移回根目录。支持拖动文章，或通过文章的右键菜单移动。

可以设置密码导出加密备份，包含工作空间内的文件、目录分类以及模型服务配置和密钥；请将备份存到工作空间以外的位置，并妥善保存密码。导入时需输入密码并选择上级目录，应用会创建一个新目录，不覆盖同名目录；恢复的密钥会交由目标设备的系统安全存储保护。备份不支持符号链接，文件总大小上限为 256 MB。选题记录和批量创作任务包含在工作空间备份中。

界面使用浅色外观，可在设置中选择主题配色；配置保存在当前设备上。

联网搜索使用当前文案模型服务的 Responses API 和 `web_search` 工具；服务和模型必须支持该接口。普通文案接口兼容并不保证支持联网搜索。模型整理的联网摘要和来源需要打开原文核查。

## 版本发布

项目通过 GitHub Actions 在推送版本标签时构建 Windows x64 安装程序和 macOS（Apple Silicon 与 Intel）安装包，并在构建均成功后创建 GitHub Release。标签必须与 `package.json` 中的版本一致，例如 `v0.0.1`。

后续发布时，先修改 `package.json` 和 `package-lock.json` 中的版本、提交并推送代码，再推送对应标签。自动构建的安装包可在 GitHub 仓库的 Releases 页面下载。

Windows 和使用固定证书签名的 Mac 版本支持应用内检查、下载和重启更新。Mac 从旧的未签名版本首次迁移时需要手动安装签名版本；自签名版本未经过 Apple 公证，系统可能显示安全提示。正式签名证书及更新服务器配置见 [Mac 自签名更新说明](docs/mac-update-signing.md)。
