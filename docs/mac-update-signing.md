# Mac 自签名更新

Mac 自动更新要求各版本使用同一张代码签名证书和对应私钥。自签名不等于 Apple 公证，首次安装仍可能遇到 macOS 安全提示；需要先人工核对来源并将应用安装到可写目录。现有未签名版本没有可验证的相同签名，首次迁移时需由用户手动下载安装新的签名版；不要通过自动更新覆盖未签名版本。手动替换前应保留原应用及数据备份，验证设置和密钥仍可读取。

正式证书必须独立生成，不能使用本地实验用的临时证书。以加密 PKCS#12 格式离线备份私钥，限制访问并留存恢复副本；固定证书的 SHA-1 指纹用于核对身份，不是私钥。证书丢失、更换或过期时不能假设旧版可自动接受新签名，需另行验证并规划人工迁移。不要把证书、私钥、密码写入仓库、安装包或日志。

发布前在 GitHub Actions 仓库 Secrets 配置：

- `LINGGAO_MAC_P12_BASE64`：正式 PKCS#12 文件的 Base64 内容。
- `LINGGAO_MAC_P12_PASSWORD`：该文件的密码。
- `LINGGAO_MAC_CERT_SHA1`：固定证书的 40 位十六进制 SHA-1 指纹。

Mac 构建在临时钥匙串导入证书，限定代码签名信任，核对指纹并强制签名；构建结束后删除临时钥匙串与信任设置。发布脚本生成同时包含两种架构的 `latest-mac.yml`，校验对应 ZIP 大小和 SHA-512。实际发布前必须先由服务器管理员部署本仓库中的 `scripts/publish-update-server.py` 新版本，旧接收程序不接受新增文件；此仓库修改不会自动更新服务器。

此流程仍需在实际 CI 环境及 Intel Mac 上验证，尤其要验证签名、安装与升级。不要使用本地实验结果代替正式构建验证。用户目录、应用标识和 Keychain 访问要求必须保持兼容，跨签名和首次迁移时应使用测试密钥验证。
